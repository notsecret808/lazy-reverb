# Lazy Reverb

Slowed + reverb и бас-буст для **Zen Browser** и Firefox 128+. Расширение меняет скорость вместе с тоном, добавляет стереореверберацию и усиливает бас на YouTube, YouTube Music и SoundCloud. Звук обрабатывается в браузере: без сервера, аккаунта и скачивания трека.

## Установка в Zen

1. Откройте `about:debugging#/runtime/this-firefox` в Zen.
2. Нажмите **Загрузить временное дополнение…** (Load Temporary Add-on).
3. Выберите `manifest.json` из папки проекта.
4. Обновите открытые вкладки YouTube и SoundCloud.
5. Включите трек, откройте **Lazy Reverb** в меню расширений и нажмите **Лениво**.

Временное дополнение удаляется при перезапуске браузера. Для постоянной установки нужна подписанная сборка Mozilla; проект пока не опубликован и не подписан. Отключать проверку подписей не требуется.

При обновлении проекта нажмите **Перезагрузить** у Lazy Reverb на странице `about:debugging`. Затем обновите музыкальные вкладки: открытая страница продолжает использовать старый движок до перезагрузки.

## Быстрый доступ в Zen

1. Нажмите значок расширений (пазл) на панели Zen.
2. Нажмите правой кнопкой мыши на **Lazy Reverb** и выберите **Закрепить на панели инструментов** (Pin to Toolbar).

Панель также открывается сочетанием **Alt+Shift+L**. Если сочетание занято, откройте `about:addons` → шестерёнка → **Управление сочетаниями клавиш расширений** и назначьте другое.

В компактном режиме Zen панель инструментов может быть скрыта; сочетание клавиш позволяет открыть Lazy Reverb без поиска значка. Закрепление значка не меняет временный характер установки. Инструкция Zen: https://docs.zen-browser.app/user-manual/extensions.

Если `about:debugging` сообщает, что Firefox новее Zen, но сравнивает `159.0.1` с `1.24.1b`, это известное ложное предупреждение DevTools: https://github.com/zen-browser/desktop/issues/10158. Оно не блокирует загрузку дополнения.

## Управление

| Настройка | Действие |
| --- | --- |
| Аудиоэффекты | Включает обработку только в текущей вкладке. Выключение восстанавливает скорость и сохранение тона, которые были до включения. |
| Скорость | От 0,50× до 1,00×. При замедлении тон понижается. |
| Реверберация | Доля обработанного сигнала от 0 до 60 %. Хвост реверберации — 2,8 с. |
| Бас-буст | От 0 до +12 дБ, полочный фильтр низких частот на 200 Гц. Выходное усиление компенсируется: высокие частоты становятся тише относительно баса, что снижает риск перегруза. |
| Мягко / Лениво / Глубоко | Готовые сочетания скорости и реверберации; нажатие сразу включает эффект. |

Скорость, сила реверберации и бас-буст сохраняются локально. Новая вкладка и обновлённая страница начинают с выключенной обработкой. Настройки продолжают действовать при смене треков без перезагрузки страницы. Чтобы использовать только бас-буст, установите скорость 1,00×, реверберацию 0 % и включите обработку. Пресеты меняют скорость и реверберацию, сохраняя выбранный бас-буст.

## Нагрузка на браузер

- Код страницы загружается только на YouTube и SoundCloud. Нет фонового процесса, опроса по таймеру или наблюдения за всеми изменениями DOM.
- Пока обработка выключена, фильтр баса и свёртка реверберации не создаются. После выключения их ветки отсоединяются, буфер реверберации освобождается. Простые обработчики событий плеера остаются.
- Если реверберация равна 0 %, свёртка не работает; при бас-бусте 0 дБ фильтр отсоединён. Для одного замедления обычного медиаплеера AudioContext не создаётся.
- После первого подключения к обычному медиаплееру остаётся простой путь Web Audio для исходного звука. Приостановка этого контекста заглушила бы музыку. Полностью убрать его можно обновлением страницы с выключенной обработкой. Для аудиографа сервиса остаётся простой проход через два GainNode.

Нулевая нагрузка не обещается. Структурные тесты проверяют отключение обработки и отсутствие роста графа после повторных включений; отдельный performance-гейт измеряет CPU и память в Zen.

## Ограничения

- Реверберация и бас-буст недоступны для защищённого DRM-аудио и некоторых внешних потоков без разрешения CORS. Такие элементы не перенаправляются в Web Audio, чтобы сохранить звук; замедление остаётся доступным.
- Если браузер приостановил AudioContext, нажмите Play или щёлкните по странице.
- Обработка действует на звук плееров в основной странице, включая рекламу. Встроенные плееры в сторонних iframe не поддерживаются.
- После удаления или перезагрузки дополнения обновите музыкальную вкладку: её аудиограф живёт до перезагрузки страницы.
- Изменения в плеерах сервисов могут потребовать обновления расширения. Проверка локального аудиодвижка не заменяет прослушивание на самих сервисах.

## Устройство

Без зависимостей и сборщика. `engine.js` загружается в основном JS-контексте страницы до её скриптов. Для обычных медиаплееров он подключает Web Audio-источник; для графа, созданного сервисом, перенаправляет соединения с `AudioContext.destination` через общий dry/wet-узел. Это позволяет не создавать второй источник для уже подключённого элемента. Скрытые `new Audio()` обнаруживаются через вызов `play()`.

При выключении остаётся только путь `input → dry → destination` с единичным усилением. Ветки фильтра и реверберации отсоединяются. Источник остаётся подключённым: повторное создание MediaElementAudioSource для того же элемента запрещено Web Audio API. Новые плееры обнаруживаются при воспроизведении; одноразовый поиск существующих элементов выполняется при включении обработки. OfflineAudioContext и соединения между обычными узлами не перехватываются. `connect()` и `disconnect(destination)` используют одно и то же перенаправление.

Разрешения ограничены YouTube и SoundCloud, доступом к внедрению кода и локальным настройкам. Нет фонового процесса, сетевых запросов, аналитики или удалённого кода. Странице доступен только API управления её собственным эффектом; API расширений остаются в панели.

## Проверка и упаковка

Проверено 21 ноября 2026 г.: 27 модульных тестов, 12 сценариев Playwright в Firefox 159.0 и установка дополнения с проверкой аудиографа в Zen 1.24.3b проходят. Бас-буст подтверждён частотной характеристикой реального фильтра; отключение свёртки — освобождением её буфера.

Функциональный гейт одной командой:

```sh
python3 tools/test.py --browser /opt/zen/zen
```

Тот же функциональный гейт доступен как `npm run check`. Отдельный гейт производительности: `npm run check:perf`.

Performance-гейт измеряет только DSP на одном непрерывно работающем AudioContext с зацикленным стереосигналом AudioBufferSource. Контекст создаётся настоящим Play-кликом и не пересоздаётся между режимами. Сравниваются прямой нативный маршрут, выключенный движок, включённые эффекты, повторное выключение и прямой нативный маршрут в конце. Он использует медиану четырёх проб по 3 с для каждого режима после прогрева. CPU всей группы процессов браузера измеряется в процентах одного ядра; память — PSS. Декодирование HTML-медиа, изменение скорости и живые страницы сервисов в этот замер не входят.

Начальные бюджеты заданы в `performance-budget.json`:

| Проверка | Допустимое превышение над контрольным воспроизведением |
| --- | --- |
| CPU при выключенной обработке, включая повторное выключение | 5 процентных пунктов одного ядра |
| CPU с реверберацией 25 % и бас-бустом +6 дБ | 20 процентных пунктов одного ядра |
| Память PSS | 64 МиБ над исходным нативным маршрутом; сохранение памяти в последнем контрольном режиме не маскирует превышение |

Код выхода `0` означает прохождение, `1` — превышение бюджета, `2` — шумные или неполные данные. Сильный дрейф контрольных замеров или нестабильность центральных проб не дают объявить успех. Отчёт сохраняется в `dist/performance-zen.json`. Один синтетический плеер не воспроизводит нагрузку всей страницы YouTube или SoundCloud.

Последний DSP-прогон 21 ноября 2026 г. в Zen 1.24.3b прошёл гейт. Бюджеты не повышались.

| Режим | CPU, % одного ядра | Память всей группы процессов Zen, МиБ PSS |
| --- | ---: | ---: |
| Нативный маршрут до эффекта | 5,47 | 409,7 |
| Реверберация 25 %, бас-буст +6 дБ | 15,93 | 433,5 |
| После выключения | 5,62 | 408,5 |

В этом сценарии обработка добавила около 10,5 процентного пункта одного ядра и 24 МиБ PSS; после выключения показатели вернулись почти к исходным. Это не гарантия такой же нагрузки на любом устройстве или на целой странице сервиса. Предыдущий стенд с пересозданием HTML-медиаплеера давал `inconclusive` из-за autoplay; он заменён DSP-стендом с одним контекстом.

Для аудиотеста нужен установленный Zen или Firefox. Браузерные сценарии используют Playwright с отдельным тестовым Firefox. Первичная установка зависимостей:

```sh
npm ci
node node_modules/playwright/cli.js install firefox
```

Все эти зависимости нужны только разработчику и не входят в архив расширения. Тесты используют временные профили и контексты, не изменяют рабочий профиль и завершают запущенные браузеры после проверки.

Отдельные проверки:

```sh
node tests/engine.test.cjs
node tests/popup.test.cjs
python3 tools/firefox-smoke.py
npm test
```

- Тесты движка: восстановление скорости и тона, скрытые плееры, смена плеера, CORS, проверка значений, повторное включение и отключение веток обработки.
- Тесты панели: очередь быстрых изменений, сохранение настроек, миграция старых настроек, неподдерживаемые адреса, ошибки внедрения кода и хранилища.
- Тесты performance-гейта: превышение CPU и памяти, шумные и неполные данные, дрейф контрольных замеров и отдельный всплеск планировщика.
- Браузерные аудиотесты: реальная свёртка с хвостом, частотная характеристика бас-буста, освобождение буфера и панель дополнения.
- Playwright: пользовательские сценарии панели и движка в настоящем Firefox — пресеты, клавиатура, настройки, изоляция вкладок, смена плеера, перезагрузка, CORS и режим одного замедления. Сеть перехватывается тестовым маршрутизатором; внешние запросы запрещены. Исходные `popup.html`, `popup.js`, `popup.css` и `engine.js` исполняются без изменений.

Playwright не поддерживает установку расширений Firefox. Поэтому в этих сценариях API `browser.*` заменены тестовым мостом: код внедрения из панели действительно выполняется в странице плеера, а настройки хранятся в памяти теста. Проверка установки настоящего дополнения и реальной обработки аудио выполняется отдельным тестом в Zen. Нативная панель инструментов Zen и горячая клавиша остаются ручными проверками.

При сбое Playwright сохраняет трассу и HTML-отчёт. Открыть отчёт: `node node_modules/playwright/cli.js show-report`.

Эти проверки не заменяют прослушивание живых треков на самих сервисах. Пользователь подтвердил работу версии 0.1.0 в Zen; изменения 0.2.0 проверяются локальными тестами.

Упаковка: `python3 tools/package.py` создаёт `dist/lazy-reverb-0.2.0.zip` только с файлами расширения. Архив предназначен для временной загрузки или отправки на подпись, а не для постоянной установки без подписи.
